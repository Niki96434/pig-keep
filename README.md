# 🐷 Pig Keep

Pig Keep - оптимизированное local-hosted веб-приложение для ведения заметок, направленное на борьбу с прокрастинацией и повышение вовлечённости пользователей через геймификацию с виртуальным питомцем.

### Основные цели MVP:
- Gamification: повышение вовлечённости и удержания пользователей за счёт взаимодействия с виртуальным питомцем.
- Performance & Reliability: оптимизация производительности и повышение надёжности приложения с помощью виртуализации списков данных

## Сценарий

1.Базовый прогресс: активность пользователя за день подсчитывается и пользователь получает XP, отвечающее за уровень удовольствия питомца и HP для поддержания жизни питомца.\
2.Активность: при использовании основного функционала (создание, редактирование, архивация заметок) у питомца растет скрытый параметр - индекс удовольствия.\
3.Если пользователь совсем не использует приложение заметок(основной продукт),то питомец теряет свои HP, вплоть до того, что питомец может заболеть/уснуть.

## Запуск проекта (local-hosted)

### 1. Запуск боевой базы данных в Docker

Для запуска убедитесь, что у вас установлен Docker и плагин `docker compose`.

1. Убедитесь в наличии конфигурации переменных окружения:
   ```bash
   cp .env.example .env
   ```
2. Запустите контейнер с базой данных в фоновом режиме:
   ```bash
   docker compose up -d
   ```
3. Проверьте статус контейнера:
   ```bash
   docker compose ps
   ```
4. Просмотр логов:
   ```bash
   docker compose logs -f
   ```
5. Остановка контейнера:
   ```bash
   docker compose down
   ```
Сервис будет доступен на `http://localhost:5432`

## Особенности реализации

- Изоляция: Сервисы backend и frontend полностью автономны, не имеют общих файловых зависимостей.
- SSOT Контракт: Спецификация OpenAPI 3.1 генерируется на стороне бэкенда и выступает единственным источником истины.
- Типобезопасность: Фронтенд работает через нативный типизированный клиент openapi-fetch, без шаблонного кода для сетевых запросов.

1. Backend:

- Codebase-first подход для изменения схем БД(миграции) с помощью drizzle-kit.(Схема как источник истины).
  Создается схема Drizzle для TS, с помощью `drizzle-kit generate` создается migration.sql на основе обновленной схемы. Чтобы применить её к самой БД, используется `drizzle-kit migrate`.

- Multi-staged сборка для Dockerfile. Она изменяет размер конечного образа за счет избавления от зависимостей, нужных для сборки приложения.

- Full-text search(полнотекстовый поиск). Он реализован для более гибкого поиска(не по полному вхождению) с помощью встроенных функций PostgreSQL. В отличие от простого ILIKE/LIKE, полнотекстовый поиск в PG поддерживает лексемы (нормализованные слова без суффиксов и приставок).Без индексов PG обычно медленно проверяет весь список в таблице, поэтому в приложении я использовала функциональный GIN-индекс, который вычисляет вектор на лету по SQL-выражению(to_tsvector).Таким образом, вектор экономит место в таблице, когда критически важно сохранить место на диске.

- Сохранение даты в виде ISO-строк и передача этих строк клиентской части, чтобы избежать конфликтов между Date и string.

- Я настроила корректное завершение работы HTTP-сервера и БД в Docker-контейнере. Для уменьшения времени простоя и мгновенного развертывания я создала функцию shutdown, обрабатывающую сигналы SIGTERM и SIGINT. В этой функции я дожидаюсь остановки приема запросов к серверу, затем закрываю пул соединений с БД, и только потом завершаю работу через process.exit(0). Также я учла проблему постоянных (keep-alive) соединений: чтобы пустые сокеты не создавали временной простой при закрытии сервера, я добавила их очистку.

- Двойная защита базы данных: проверка флага NODE_ENV === 'test' перед инициализацией базы и проверка части имени тестовой базы данных, чтобы не очистить боевую БД.

2. Frontend

- Реализован [api-модуль](https://github.com/Niki96434/google-keep/blob/main/frontend/src/shared/api/notesApi.ts) для инкапсуляции сетевых запросов и изоляции логики работы с сетью от UI.(Separation of Concerns)

- Multi-staged сборка для легковесного образа и раздача статики через веб-сервер Caddy. Использован образ на основе Alpine Linux, который ускоряет загрузку образа и экономит место.
